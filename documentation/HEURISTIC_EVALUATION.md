# MediRemind — Heuristic Evaluation (Nielsen's 10 Usability Heuristics)

This checklist evaluates the **MediRemind** prototype against Jakob Nielsen's 10 Usability Heuristics, as required by the project specification. You can update the **Pass / Needs Work** status again after running your real elderly usability tests.

---

## Heuristic Evaluation Checklist

| # | Heuristic Name | How It Applies to MediRemind | Implementation Evidence in Prototype | Status (`Pass` / `Needs Work`) | Notes & Possible Version 2 Improvements |
| :---: | :--- | :--- | :--- | :---: | :--- |
| **1** | **Visibility of System Status** | Elderly users must always know whether a medicine was saved, taken, snoozed, or missed without guessing. | - Progress bar & counter on Home (`1 of 4 taken today`).<br>- `"Medicine saved!"` toast after adding.<br>- Full-screen `"Well Done!"` confirmation after pressing **Taken**.<br>- Status pills (`✓ Taken`, `⏰ Due Now`, `⏱ Remind in 10 min`, `✕ Missed`). | **Pass** | Verify during usability testing whether toast duration (`5.5s`) is long enough for slower elderly readers; lengthen if needed in Version 2. |
| **2** | **Match Between System and the Real World** | Interface should speak everyday human language instead of technical or clinical jargon. | - Full **English** and simple **Urdu (RTL)** switching.<br>- Familiar local daily time words: **Subah, Dopahar, Shaam, Raat** (صبح، دوپہر، شام، رات).<br>- Simple dose words (`1 Tablet` / `1 گولی`, `1 Spoon` / `1 چمچ`). | **Pass** | Check with real elderly Urdu speakers whether any Urdu button phrasing can be made even shorter or more natural. |
| **3** | **User Control and Freedom** | Users who tap the wrong button should easily go back or undo without panic. | - Visible **Back (`←`)** button on Home, Add, Reminder, and History.<br>- **Undo** button on Toast after Taken, Add, or Delete.<br>- `"Pressed by mistake? Undo"` button right on the Well Done confirmation screen.<br>- **Cancel** button on Delete/Reset popups. | **Pass** | Test whether elderly users notice the Undo button on the bottom toast banner. |
| **4** | **Consistency and Standards** | Colors, icons, button sizes, and navigation should stay predictable across all 5 screens. | - Same 4-tab bottom bar (`Home`, `Add`, `Alert`, `History`) with icon + label.<br>- Same top bar pattern (Back on start side, Language/Help on end side).<br>- Consistent 3-color meaning: Deep Teal = primary action, Forest Green = Taken/positive, Brick Red = Missed/delete. | **Pass** | Keep Screen 4 (Reminder Alert) intentionally free of bottom nav so users stay focused on **Taken**, while keeping the standard top **Back** button. |
| **5** | **Error Prevention** | Design should prevent accidental deletions, mis-taps, and typing errors before they happen. | - `"Are you sure?"` modal dialog before deleting a medicine or resetting demo data.<br>- Large buttons (`>= 52px` tall) with generous spacing.<br>- Quick-tap presets for Time (`Subah/Dopahar/Shaam/Raat`) and Dose (`1 Tablet`, etc.) to minimize typing errors. | **Pass** | Consider adding duplicate-medicine warning in Version 2 if users accidentally save the same medicine twice at the same time. |
| **6** | **Recognition Rather Than Recall** | Users should recognize medicines and actions on screen instead of memorizing them. | - Reminder Alert shows large medicine name, recognizable SVG visual (White Pill, Capsule, Round Pill, Syrup), time, and dose together.<br>- Every icon across the entire app is paired with a clear text label—zero icon-only buttons.<br>- No hidden hamburger menu. | **Pass** | In a future native app (FYP), letting users attach a real camera photo of their medicine box would make recognition even stronger. |
| **7** | **Flexibility and Efficiency of Use** | Simple for beginners, fast for daily repeat use. | - One-tap quick **Taken** button directly on Home cards (1 tap goal).<br>- Quick time & dose preset chips on Add Medicine (saving Panadol at 8 pm takes under 6 taps).<br>- Extra Large text size option in Help for users with weaker eyesight. | **Pass** | Check during Task 2 whether elderly users prefer the quick `Raat (8:00 PM)` button or the HTML time picker. |
| **8** | **Aesthetic and Minimalist Design** | Remove clutter so each screen focuses on one primary task. | - One main goal per screen (Welcome = start/language, Home = today's list, Add = simple form, Alert = take medicine, History = view log).<br>- Calm warm off-white surface (`#FAF8F5`), high-contrast text, only 3 primary colors, no decorative clutter. | **Pass** | Observe on small physical phone screens whether the demo simulation box on Screen 4 distracts elderly users during Task 3; if so, move demo triggers into a small collapsed strip in Version 2. |
| **9** | **Help Users Recognize, Diagnose, and Recover from Errors** | Validation errors must be polite, clear, and explain exactly how to fix the issue. | - Submitting an empty Add Medicine form highlights invalid fields in red, moves focus to the first missing input, and displays plain-language messages like `"Please write the medicine name."` / `"براہ کرم دوائی کا نام لکھیں۔"`. | **Pass** | Ensure the red error box scrolls clearly into view on very small mobile screens. |
| **10** | **Help and Documentation** | Clear help must be visible and effortless to access when stuck. | - Visible **`? Help`** button on Welcome, Home, Add, and History.<br>- Concise 4-step instructions + one-tap **Play Voice Guide** button (reads steps aloud slowly in English or Urdu). | **Needs Work (Device-Dependent Voice)** | Web Speech API Urdu voice availability varies by phone/browser OS. In Version 2 / FYP, bundled pre-recorded Urdu MP3 voice clips would guarantee clear Urdu speech on every device. |

## Summary of Self-Evaluation

- **Heuristics Passing:** 9 of 10 fully implemented and verified in prototype.
- **Honest Area Marked "Needs Work":** Heuristic #10's spoken Urdu voice quality depends on the browser's installed speech synthesis voices (whereas English speech and visual 4-step help work everywhere). Mentioning this honest evaluation point in your report and viva shows strong, critical HCI thinking!
